# 코스 추천 — "취향 비슷한 새 곳"(similar) 스코어링 로직

> `GET /api/v1/courses/similar` 백엔드 구현 시 참고 문서
> 관련 논의: 리뷰 태그 기반 유사도 계산 방식 (최초 아이디어 → 팀 논의 → 확정)

---

## 1. 배경

- AI(LLM)는 코스 생성에 관여하지 않는다. `similar` 모드는 **리뷰 태그 + 반려동물 정보 + 최신성**을 결정론적으로 계산해 점수를 매기는 방식이다.
- 후보: 로그인한 사용자가 아직 안 가본(리뷰/판별 이력 없는) 동반 가능 시설.
- "안 가본 곳" 판정은 `PetCheck`가 아니라 `PetSatisfaction`/`Review`(실제 방문 기록) 기준으로 한다.

## 2. 전제 조건 — 리뷰 최소 태그 3개

- 리뷰 작성 시 `tags`는 **최소 3개 이상 필수**로 강제한다 (Request Body validation).
- **소급 적용하지 않는다.** 서비스가 아직 출시 전이므로 기존 리뷰 데이터가 없어 신경 쓸 필요 없음 — 신규 리뷰부터 바로 최소 3개로 적용.

## 3. 유사도 계산 로직

### 3.1 태그 겹침 — 태그 종류에 따라 가중치 차등 적용

태그를 두 그룹으로 나눈다.

| 그룹 | 태그 | 가중치 |
|---|---|---|
| 반려동물 경험 태그 (가중치 높음) | `LARGE_SPACE`, `LARGE_DOG`, `OFF_LEASED_AVAILABLE`, `PET_MENU_EXIST`, `STAFF_WELCOMING`, `WATER_EXIST`, `WASTE_BAG_PLACED` | **× 2.0** |
| 일반 편의 태그 (가중치 낮음) | `PARKING_CONVENIENT`, `QUIET_ATMOSPHERE`, `OUTDOOR` | **× 1.0** |

내 취향 프로필(좋아한 시설들에 내가 남긴 태그 집합)과 후보 시설의 리뷰 태그가 겹칠 때마다, 해당 태그의 가중치를 합산한다.

### 3.2 반려동물 속성 매칭 — 필터가 아니라 보너스

**중요: kind(종)가 다르다고 후보에서 제외하지 않는다.** 새·소동물처럼 리뷰가 절대적으로 적은 종을 kind로 필터링하면 추천 자체가 안 나올 수 있기 때문. 대신 매칭 시 보너스 가중치만 부여한다.

| 조건 | 보너스 배율 |
|---|---|
| 리뷰 작성자의 반려동물과 `kind`(DOG/CAT/BIRD 등)가 같음 | **× 1.5** |
| 리뷰 작성자의 반려동물과 `breedSize`(SMALL/MEDIUM/LARGE)가 같음 | **× 1.2** |

- 몸무게는 정확한 kg 매칭이 아니라 이미 있는 `breedSize`(SMALL/MEDIUM/LARGE) 구간을 그대로 재사용한다 — 정확한 kg 매칭은 데이터 희소성 문제로 부적합.
- kind와 breedSize 둘 다 안 맞아도 후보에서 빠지지 않으며, 보너스만 없을 뿐 기본 태그 겹침 점수는 그대로 반영된다.

### 3.3 리뷰 최신성 — 4단계 구간 가중치

`review.visitedAt` 기준으로 리뷰가 오래될수록 반영 비중을 낮춘다.

| 방문 시점 | 가중치 |
|---|---|
| 1개월 이내 | **× 1.0** |
| 1~3개월 이내 | **× 0.7** |
| 3~6개월 이내 | **× 0.4** |
| 6개월 이후 | **× 0.2** (완전 배제하지 않음) |

### 3.4 최종 공식

리뷰 하나하나에 대해 아래를 계산한 뒤, 같은 시설의 모든 리뷰에 대해 합산한다.

```
리뷰 점수 = 태그겹침점수(그룹별 가중치 합)
          × 최신성가중치
          × (같은 kind ? 1.5 : 1.0)
          × (같은 breedSize ? 1.2 : 1.0)

시설 점수 = Σ(해당 시설에 달린 모든 리뷰의 리뷰 점수)
```

**예시**
- 리뷰 A: 겹치는 태그 = `LARGE_SPACE`(경험, 2.0) + `PARKING_CONVENIENT`(일반, 1.0) = 3.0
- 방문 시점: 2개월 전 → × 0.7
- 같은 kind(DOG) → × 1.5
- 다른 breedSize → × 1.0

```
리뷰 A 점수 = 3.0 × 0.7 × 1.5 × 1.0 = 3.15
```

### 3.5 `petScore`와의 중복 방지

`facilities.petScore`(친화도 점수)는 이미 리뷰 기반 집계값이므로, `similar` 스코어링에는 **포함하지 않는다.** 순수하게 태그 겹침 + 반려동물 속성 매칭 + 최신성만 사용해 이중 가중을 방지한다.

## 4. Response 예시 (추천 근거 노출)

```json
{
  "facilityId": 12,
  "name": "속초 파도 카페",
  "matchedTags": ["LARGE_SPACE", "OFF_LEASED_AVAILABLE"],
  "matchedByKind": true,
  "matchedByBreedSize": false,
  "reason": "넓은 공간·목줄 풀기 가능이 비슷해요 (같은 강아지 리뷰 기준)"
}
```

## 5. 초기값 요약 (튜닝 전 시작점)

| 항목 | 값 |
|---|---|
| 경험 태그 가중치 | × 2.0 |
| 일반 편의 태그 가중치 | × 1.0 |
| 같은 kind 보너스 | × 1.5 |
| 같은 breedSize 보너스 | × 1.2 |
| 리뷰 1개월 이내 | × 1.0 |
| 리뷰 1~3개월 이내 | × 0.7 |
| 리뷰 3~6개월 이내 | × 0.4 |
| 리뷰 6개월 이후 | × 0.2 |

> 위 수치는 모두 **초기 추정값**이다. 실제 서비스 데이터가 쌓이면 추천 결과의 체감 품질을 보면서 조정한다.

## 6. 남은 논의 사항

- 위 가중치 수치들의 최종 확정 (팀 리뷰 필요)
- 리뷰 최소 태그 개수(3개) 정책은 신규 리뷰부터 적용 — 출시 전이므로 소급 이슈 없음
- `matchedTags`가 여러 리뷰에 걸쳐 반복 등장할 때 프론트 표시 방식(가장 많이 겹친 태그만 노출할지, 전체 노출할지)
